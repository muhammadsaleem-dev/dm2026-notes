Data Preprocessing

Preparing the raw ingredients
Splitting → Imputing → Encoding → Scaling

Machine learning algorithms are essentially just giant calculators. They can't read text, they crash if a value is missing, and they get confused if you don't put everything on the same scale. Preprocessing is the art of translating raw, messy real-world data into perfect numbers.

High-Level Overview

Our concrete running example: The Titanic Dataset.

The Running Example

Throughout this module, we will be preparing the classic Titanic dataset. We want to predict if a passenger survived based on their Age, Ticket Fare, Cabin, and Port of Embarkation. But the data is messy: Ages are missing, Cabins are full of text, and Fare values are way larger than Age values.

The Golden Rule of Leakage

Before we do ANY cleaning (like filling missing ages with the average age), we must lock away 20% of our data for testing. If we calculate the "average age" using all passengers, the test set's data will "leak" into our training phase. Always split first.

1

The Train/Test Split

The Code Reality

from sklearn.model_selection import train_test_split

# Let's pretend X contains our features (Age, Fare, Cabin) and y contains survival (0 or 1)
# Step 1: Lock away 20% of the data!
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.2, random_state=0)
🚨
Exam Trap: Data Leakage

This is a favorite exam trick! Data Leakage is when information from the Test set accidentally "leaks" into the Training set (e.g., if you scale or impute data before splitting). It causes the model to look highly accurate during training, but fail miserably in the real world. Always split first.

🎯
Exam takeaway
  • random_state: Setting this seed (e.g., to 0 or 42) ensures that you get the exact same random split every time you run the code. Crucial for reproducible research!
2

Handling Missing Data (Imputation)

Numerical vs Categorical

Numerical (e.g. Age)

We usually fill missing numbers with the Median (less sensitive to extreme outliers like billionaires) or the Mean. Often, we also add a new binary column "Age_was_missing" (0 or 1) so the model knows the data was guessed.

Categorical (e.g. Cabin)

We can't take the average of text! We usually replace missing categorical values with the literal string "Missing", treating the absence of data as its own unique category.

The Code Reality

import numpy as np

# 1. Add a missing indicator (1 if missing, 0 if not)
X_train['Age_was_missing'] = np.where(X_train['Age'].isnull(), 1, 0)
X_test['Age_was_missing']  = np.where(X_test['Age'].isnull(), 1, 0)

# 2. Fill numerical NaNs with the Median of the TRAIN set
median_age = X_train['Age'].median()
X_train['Age'].fillna(median_age, inplace=True)
X_test['Age'].fillna(median_age, inplace=True) # NEVER use test median!

# 3. Fill categorical NaNs with the word 'Missing'
X_train['Cabin'].fillna('Missing', inplace=True)
X_test['Cabin'].fillna('Missing', inplace=True)
3

Categorical Data & One-Hot Encoding

Models can't do math on words. We must convert text to numbers.

1. Handling Rare Labels

If only 2 passengers out of 1000 embarked from port "Z", the model will just memorize them instead of learning a pattern. Best practice: Find labels that appear in less than 5% of the data, and group them into a new category called "Rare".

2. One-Hot Encoding (OHE)

If we encode ports as C=1, Q=2, S=3, the model will think S is mathematically "greater" than C. This is false! Instead, we create separate binary columns for each port.

The Dummy Variable Trap (k-1)

If a person is not Male, they must be Female. If we create a column for "Is_Male" and "Is_Female", they are perfectly correlated and will break linear models (Multicollinearity). To fix this, if a category has k labels, we only create k-1 columns. We drop the first one.

The Code Reality

from sklearn.preprocessing import OneHotEncoder

# Initialize encoder. drop='first' gives us the k-1 columns to avoid the trap!
# handle_unknown='ignore' ensures it doesn't crash if it sees a weird port in the test set.
encoder = OneHotEncoder(drop='first', handle_unknown='ignore', sparse=False)

# Fit on training data ONLY, then transform both train and test!
X_train_encoded = encoder.fit_transform(X_train[['Embarked']])
X_test_encoded = encoder.transform(X_test[['Embarked']])
💡
Cheat Sheet: Which models need One-Hot Encoding?

A classic exam question asks you to identify models that require OHE. Here is the rule of thumb:

  • REQUIRE OHE: Distance-based or Math-equation models (Logistic Regression, Linear Regression, SVMs, K-Means, Neural Networks). They cannot do math on words.
  • DO NOT REQUIRE OHE: Tree-based models (Decision Trees, Random Forests, XGBoost). They can natively split on categorical labels (e.g., "Is Color == Red?").
4

Scaling the Variables

We use StandardScaler to force every numerical column to have a Mean of 0 and a Standard Deviation of 1 (Z-score). Alternatively, we use MinMaxScaler to squash every number between 0 and 1.

The Code Reality

from sklearn.preprocessing import StandardScaler, MinMaxScaler

# 1. StandardScaler (Mean=0, Std=1)
scaler = StandardScaler()

# GOLDEN RULE: Fit only on the training data!
X_train_scaled = scaler.fit_transform(X_train[['Age', 'Fare']])

# We ONLY transform the test data.
X_test_scaled = scaler.transform(X_test[['Age', 'Fare']])


# 2. MinMaxScaler (Values between 0 and 1)
minmax = MinMaxScaler()
X_train_minmax = minmax.fit_transform(X_train[['Age', 'Fare']])
X_test_minmax = minmax.transform(X_test[['Age', 'Fare']])

Test Yourself (Concept Drills)

Test your knowledge with essential exam-style concept questions.

Concept check A data scientist applies StandardScaler().fit_transform(X) on their entire dataset, and then splits it into X_train and X_test. What terrible mistake have they made?

Data Leakage. By fitting the scaler on the entire dataset, information about the Test Set (like its mean and standard deviation) has leaked into the training data. You must always split first, fit the scaler on X_train only, and then just transform X_test.

Name it You have a variable containing cities (New York, London, Paris, Tokyo). You One-Hot Encode them to feed into a Logistic Regression model. How many binary columns should you create?

3 columns (k-1). This avoids the Dummy Variable Trap (multicollinearity). If a row is 0 for New York, 0 for London, and 0 for Paris, the model mathematically deduces they must be in Tokyo.

Reorder Put the following Machine Learning steps in the correct chronological order:
  1. A. Determine validation metrics
  2. B. Divide data into train/test/validate
  3. C. Prototyping (Modelling & Hyperparameter tuning)
  4. D. Determine sample size
  5. E. Preprocessing (Encoding, Scaling, Imputing)

D → B → E → A → C
