1

Decision Trees

Classification is supervised learning: learn the pattern linking features to a known label, then apply it to new, unlabeled instances.

A tree is built from nodes (attribute tests), branches (outcomes), and leaves (class predictions, possibly as a probability split). The goal is to ask as few questions as possible while still generalizing well.

Choosing the best split: entropy & information gain

Entropy measures how mixed/impure a set is (0 = pure, max = a 50/50 split for binary classes):

entropy(X) = − Σᵢ pᵢ · log₂(pᵢ)

Information gain of splitting on attribute a = the entropy reduction that split achieves:

gain(X, a) = entropy(X) − Σ_{v ∈ Values(a)} (|X_v| / |X|) · entropy(X_v)

The best attribute to split on is the one with the highest information gain. Worked example (7 records, predicting Mammal/Bird from color vs. whether it flies): splitting on color gains only 0.020, while splitting on fly gains 0.521 — fly is the far better, chosen split.

Overfitting, underfitting, and pruning

A tree can keep splitting on ever more specific attributes until it perfectly memorizes training data — that doesn't generalize. Plotting error against tree complexity: train error keeps falling, but test error falls then rises — the low point of the test curve is the sweet spot.

Underfitting

Too simple — fails on both train and test data.

Overfitting

Too complex — fits training noise "parrot fashion," fails to generalize.

Regularization is any technique that penalizes complexity to prevent overfitting. For trees, this is pruning: remove nodes bottom-up whenever doing so decreases validation error — this narrows the train/test gap and shifts the optimal complexity point.

Limitations

IssueDescription
Overfitting riskBuilds overly complex trees on noise, worse with small/high-dimensional data
Lower predictive powerOften less accurate than ensemble methods
InstabilitySmall data changes → completely different tree
Axis-aligned splits onlyDecision boundaries are boxy/rectangular — can't capture diagonal patterns
Quiz

"Which plot shows a decision tree's decision boundary?" — the answer is always the one with blocky, axis-aligned rectangular regions, not smooth or diagonal ones. That boxiness is the tell.

Random Forests

Growing many different trees on purpose, then letting them vote.

Quiz

If you grow multiple trees on the same data, do they learn the same splits? No — ensembles deliberately inject randomness so the trees differ from each other.

Two randomization mechanisms

  • Bagging (Bootstrap Aggregating) — draw M subsets of the training data by sampling with replacement; train one tree per subset.
  • Random Subspace Method — each tree only sees a random subset of features.

Random Forest = Bagging + Random Subspace + Decision Trees, producing N differently-trained trees. At inference, a test sample goes through every tree; the final prediction is decided by majority vote, with the vote share doubling as a confidence score (e.g. 3-of-4 trees agreeing = 75% confidence).

Analogy: instead of giving one student 6 books to summarize, split the class into groups, each reading a different subset of books and pages — the class's collective answer beats any single student's guess.

from sklearn.ensemble import RandomForestClassifier clf = RandomForestClassifier(n_estimators=20) # 20 trees

Adaptive Boosting (AdaBoost)

Instead of many independent trees, build weak learners sequentially, each one fixing the last one's mistakes.

Each weak learner is typically a decision stump (depth-1 tree).

  1. Initialize weights — every sample starts with equal weight 1/N.
  2. Train a stump, compute its say (α):
    αᵢ = ½ · ln((1 − εᵢ) / εᵢ)
    where εᵢ = the weighted error rate of stump i. Lower error → higher α → more voting power.
  3. Reweight samples — correctly classified samples shrink in weight (×e⁻ᵅ), misclassified ones grow (×e^α), then renormalize.
  4. Resample the next training set according to the updated weights, so the next stump focuses on what the current ensemble gets wrong.
  5. Repeat for T rounds.

Final prediction = weighted vote across all stumps, each weighted by its own α:

C*(x) = argmax_y Σᵢ αᵢ · [Cᵢ(x) = y]

Random Forest vs. AdaBoost

DimensionRandom ForestAdaBoost
TreesFull trees (depth is a hyperparameter)Almost always stumps (depth 1)
ComputationParallel — trees are independentSequential — each stump depends on the last
SamplingBagging: independent random subsetsBoosting: reweighted toward past mistakes
VotingEqual vote per treeWeighted vote (better stumps get more say)
OverfittingMore robust — bagging reduces varianceMore prone — keeps re-fitting to hard/outlier points
OutliersLess sensitive (averaging)Sensitive — repeatedly upweighted if hard to classify
Trade-off

Random Forest: robust and general, but harder to explain any single recommendation. AdaBoost: can reach high accuracy by refining simple rules, but is more easily thrown off by unusual/outlier records. Pick based on whether robustness or peak accuracy matters more.

Ensemble learning, summarized: Bagging = same algorithm, different data samples. Random Subspace = same algorithm, different feature subsets. Boosting = sequential models, each correcting the last.

A First Look at Explainability & Causality

This chapter's closing detour — developed in full in Chapter 7.

Explainable AI (XAI) makes a model's predictions transparent: which features drove a decision, and why. It matters most where trust, fairness, and accountability are non-negotiable — credit scoring, medical diagnosis.

Glass-box vs. black-box models
Glass-box (interpretable)Black-box (opaque)
Linear / Logistic Regression, Decision Tree, k-NN, Naive Bayes, low-dim SVMRandom Forest, Neural Nets, Gradient Boosting, high-dim SVM

Causal AI goes a step further than explainability: it asks what actually causes an outcome, not just what correlates with it. Worked illustration: a patient's longer survival time might just be because of treatment timing (a confounding artifact), not because the model's predictor is a real cause — prediction ≠ causation.

Explainable AICausal AI
FocusMaking a decision understandableUncovering true cause-and-effect
MethodFeature importance, attention, decision treesCausal inference, domain knowledge, experiments
Answers"What factors influenced this decision?""What would happen if we intervened on X?"
