1

Clustering as Unsupervised Learning

No ground-truth labels — the model learns similarity/difference directly from the data.

Most of the machine learning you've read about — including everything in Module 3 — assumes someone has already told you the right answer for every training example. That labeling is expensive. Most data you'll actually encounter doesn't come with that luxury: you have half a million e-commerce transactions and no idea, up front, which customers are "loyal," "at risk," or "one-time bargain hunters" — those categories don't exist yet. They're something you want the data to reveal, not something you already know.

That's the problem clustering solves. Instead of learning a mapping from features to a known label, it looks at unlabeled examples and asks a much more primitive question: which of these points are more similar to each other than to the rest? Group the similar ones together, and you've invented categories without anyone having pre-defined them.

A useful analogy: classification is like calling a method that already has a documented contract — isFraud(transaction) -> boolean — where someone wrote the correct return value for a training set of examples. Clustering is more like handing you a pile of objects with no equals()/hashCode() contract at all, and asking you to bucket them by "how alike they seem" using only their own field values. There's no oracle checking your work — success isn't "did I match the right answer" but "are these groupings actually useful and coherent."

If there's no "correct answer" to check clustering against, how do you know a clustering result is any good?

You judge it by internal coherence instead — are points within a group actually close together, and are the groups themselves far apart from each other? §5 covers the metrics (like the silhouette score) that quantify exactly this, in place of the accuracy-against-labels check classification gets for free.

Once a clustering model is trained, you can hand it a brand-new point and it will tell you which existing group that point most resembles — even though no one ever labeled a single training example as "loyal" or "arrhythmic."

"Similarity" means something different in each row — waveform shape, spending behavior, topic overlap, gene expression profile — clustering doesn't care what the features mean, only how close together points land once turned into numbers. That's both its power (domain-agnostic) and its main hazard (it will happily group things that are numerically close but conceptually meaningless together, if features are chosen or scaled badly — see §4). Everything in the rest of this module elaborates one idea: define "close," then find groups that are internally close and mutually far apart.

2

K-Means

Fast and simple — but only as good as its starting point.

Once you've accepted the goal — find groups of mutually similar points — you need an actual procedure. K-Means is the default answer: pick a number of groups you want, guess where their centers are, and let points and centers pull each other into a stable arrangement.

The distance metric

Before you can say two points are "close," you need to measure closeness numerically. K-Means uses squared Euclidean distance — the straight-line distance formula from geometry, just without the final square root, since skipping it doesn't change which point is nearest and saves compute:

‖x−c‖² = (x₁−c₁)² + (x₂−c₂)²

Take the difference in each coordinate, square each difference, add them up. That squaring matters a lot in practice — one dimension with a much larger numeric range than another can completely dominate the distance calculation, exactly the scaling problem in §4.

The algorithm, step by step

  1. Fix K (number of clusters) in advance.
  2. Pick K random points as initial centroids.
  3. Assign each point to its nearest centroid.
  4. Recompute each centroid as the mean of its assigned points.
  5. Repeat 3–4 until assignments stop changing or max iterations is hit.

Why does this loop ever settle down instead of running forever? Each of the two moves can only help, never hurt: reassigning a point to a genuinely closer centroid can only shrink the total squared distance, and recomputing a centroid as the mean of its points can only shrink or hold that total steady (a mean is, by definition, the point minimizing total squared distance to a fixed set of points).

🧠Two moves that each can only ever help, alternating forever, has to bottom out somewhere — that's why K-Means is guaranteed to converge.

Python note

from sklearn.cluster import KMeans; KMeans(n_clusters=2).fit(X) runs the assign/recompute loop above until convergence. .inertia_ gives you exactly the WCSS value computed by hand (2.67 above) — you never sum squared distances yourself in practice.

Local optima & inertia

Step 2 says "pick K random points as initial centroids" — and random does a lot of work in that sentence. Because the algorithm only ever moves points and centroids to decrease WCSS, it's guaranteed to stop somewhere — but "somewhere" depends heavily on where it started. A bad initial guess can lock the algorithm into a local optimum: better than every neighboring arrangement, but not the best overall. Nothing in the assign/recompute loop can ever escape a bad basin once it's fallen in, because every step is only ever allowed to reduce WCSS from where it currently stands.

This isn't hypothetical: three runs on the same data, same K, different random seeds, scored WCSS of 444.9, 349.7, and 451.4. The practical fix: run K-Means multiple times with different random seeds, and keep the run with the lowest final inertia.

Python note

random_state fixes the seed so a run is reproducible. n_init controls how many independent random-seed attempts scikit-learn runs internally before returning the best one automatically — in practice you rarely implement "try several seeds, keep the best" yourself; you raise n_init and let the object do it.

Inertia / WCSS (within-cluster sum of squares) — lower is more compactW_k = Σᵢ Σ_{x∈Cᵢ} ‖x − μᵢ‖²

Reading left to right: for every cluster i, for every point x assigned to it, take the squared distance from x to that cluster's centroid μᵢ, and sum across all clusters — exactly the 8/3 computed by hand above, generalized to K clusters.

3

Choosing K

K-Means needs K handed to it — two ways to estimate a reasonable value.

K-Means has one glaring gap: step 1 says "fix K in advance," but where does that number come from? Unlike counting distinct labels in a labeled dataset, there's no ground truth telling you how many customer segments actually exist — that's precisely what you're trying to discover.

Elbow method

Run K-Means for K=1,2,3,4,… and record the WCSS for each. As K grows, WCSS is mathematically guaranteed to shrink (more centroids can only carve the data up more finely; at K = number of points, WCSS is exactly 0). What you're looking for isn't the smallest WCSS — it's where the curve's descent sharply flattens.

Worked example

Extend the six-point dataset from §2 to a few candidate K values.

  1. K=1One centroid, the overall mean (4.83, 5). Summing squared distances from all six points gives WCSS(1) ≈ 142.83 — large, since two genuinely far-apart groups are both measured against one center sitting uselessly between them.
  2. K=2From §2: WCSS(2) = 8/3 ≈ 2.67
  3. K=3Split {P2,P3} off from P1 — clusters {P1}, {P2,P3}, {P4,P5,P6}
    {P1} contributes 0. {P2,P3} (centroid (1.5,2)) contributes 0.5. {P4,P5,P6} unchanged at 1.333
    WCSS(3) ≈ 1.83

K=1→2: WCSS falls off a cliff (drop of over 140). K=2→3: drops by less than 1. That's the elbow — a sharp bend after which extra clusters just chip away at weak internal substructure inside two clusters that are obviously two clusters. K=2 is exactly what you'd eyeball from the raw coordinates.

Watch out

The elbow is a heuristic, not an optimum: the "right" elbow is subjective, it assumes roughly spherical equal-sized clusters, it's sensitive to the same initialization randomness as K-Means itself, and it's expensive to recompute across many K values on large data. ("There is no 'optimal' solution in cluster analysis — interestingness is a subjective decision of the user." — Schubert, 2022). On real, messier data the bend is rarely this dramatic.

Gap statistic — a more principled alternative

The elbow method only ever looks at your data's WCSS curve in isolation and asks a human to eyeball the bend. The gap statistic asks a more rigorous question: compared to data with no real structure at all, how much better is my clustering actually doing?

  1. Compute log W(K) — the log within-cluster dispersion on the real data.
  2. Simulate B reference datasets drawn uniformly over the same bounding box; average their log W_unif(K).
  3. Gap(K) = (1/B)Σ log W_unif,b(K) − log W(K)
  4. Compute a standard error SE(K) across the simulations.
  5. Pick the smallest K such that Gap(K) ≥ Gap(K+1) − SE(K+1).

A uniform reference dataset is fake data scattered randomly inside the same bounding box — no structure, just noise. K-Means on pure noise still sees WCSS drop as K grows (more centroids always help a little), but smoothly, with no elbow. The gap statistic subtracts that "smooth decline from noise alone" away from your real data's decline — what's left is decline attributable to actual structure.

Worked example

True Monte Carlo simulation isn't something to do by hand, so treat the reference numbers here as illustrative stand-ins for the arithmetic. Log-scale the toy WCSS values: log W(1) ≈ 4.962, log W(2) ≈ 0.981, log W(3) ≈ 0.606. Suppose averaging log W_unif(K) over many random reference datasets gave: 5.85 at K=1, 5.20 at K=2, 4.70 at K=3 — a much more gradual decline than the real data's.

4

Where K-Means Breaks

Everything so far has been K-Means working as intended. The catch: this only works cleanly under fairly specific assumptions about your data's shape — and real data violates those assumptions constantly.

Quiz

Tested on three datasets — roughly spherical unequal-variance blobs, anisotropically stretched blobs, and moon-shaped clusters — K-Means only produced sensible clusters on the spherical blobs. It visibly misassigns points on the stretched and non-convex shapes.

Why spherical, equal-sized clusters are the hidden assumption

K-Means never explicitly assumes clusters are round — but minimizing squared distance to a single centroid per cluster implicitly favors round, compact, similarly-sized blobs, because one point (the centroid) is a poor stand-in for a cluster's shape when that cluster is elongated or of very different density than its neighbors.

Worked example

Group A is a long, thin process: points (0,0) and (16,0), genuinely elongated. Group B is tight and compact: (15,1), (17,1), (16,2).

  1. CentroidsCentroid of A = (8, 0)   Centroid of B = (16, 1.33)
  2. Where does K-Means place (16,0) — the far end of elongated group A?Squared distance to A's centroid: (16−8)²+(0−0)² = 64
    Squared distance to B's centroid: (16−16)²+(0−1.33)² ≈ 1.78

1.78 is dramatically smaller — K-Means assigns (16,0) to cluster B, even though it's a genuine member of A. A single average point is a bad geometric summary of a shape that isn't round.

Why unscaled features distort distance

Squared Euclidean distance treats every feature's numeric units as directly comparable — which they almost never are.

Worked example

Clustering on age (20–60) and income ($20,000–$200,000). Two customers differ by 5 years and $100.

  1. Squared contribution from age5² = 25
  2. Squared contribution from income100² = 10,000

Income outweighs age by a factor of 400, even though $100 is nearly meaningless while 5 years might be quite meaningful. K-Means will cluster almost entirely on income.

Python note

from sklearn.preprocessing import StandardScaler; X_scaled = StandardScaler().fit_transform(X) rescales every feature to mean 0, std 1, so no feature's raw numeric range can dominate purely from its units.

Why outliers distort centroids

A centroid is a mean, and means are notoriously sensitive to extreme values.

Worked example
  1. Three tight points: (1,1), (2,2), (3,1)Mean = (2, 1.33), sitting comfortably in the middle
  2. Add one outlier: (50,50)New mean over all four = (14, 13.5) — dragged far outside the region where three of the four "members" actually live

Every ordinary point is now measured against a centroid that no longer represents where they are.

Why categorical data doesn't fit

Squared Euclidean distance requires numbers whose magnitude of difference is meaningful. Encode color as red=1, blue=2, green=3, and K-Means treats green as "twice as different" from red as blue is (|1−3|²=4 vs |1−2|²=1) — an artifact of arbitrary numbering with no basis in categories that have no inherent order at all.

Taken together: sensitive to outliers, can converge to local optima (§2), requires similarly-scaled features, not suited to categorical data, and assumes roughly spherical, similarly-sized clusters.

Bottom line: simple, fast, and genuinely useful for quick exploratory segmentation — as long as its spherical-cluster assumption isn't badly violated.

At scale

Every iteration of the assign/recompute loop requires a full pass over every point to compute distance to every centroid; on millions of rows, repeated until convergence, that adds up fast — and has to happen again from scratch for every candidate K in the elbow method. Vanilla K-Means struggles with large data: repeated full-dataset iteration is expensive, memory grows, initialization gets harder, and high dimensionality complicates both computation and interpretation. Scalable variants exist (Mini-Batch K-Means, K-Means++); distributed tooling includes PySpark and RAPIDS.

Python note

from sklearn.cluster import MiniBatchKMeans is a drop-in alternative with the same n_clusters/.fit()/.inertia_ interface, just faster on large data at the cost of slightly noisier convergence.

5

Evaluating & Interpreting Clusters

Clustering is exploratory — the payoff is in what the groups actually mean.

Once K-Means has produced an assignment: is this clustering actually good? Unlike classification, there's no held-out label to check against — "good" has to be defined purely from the geometry of the points themselves.

Silhouette Coefficient, up close

A good cluster assignment for a point should mean two things at once: the point sits close to its own cluster, and far from every other cluster. The silhouette score turns exactly that idea into one number per point.

For a single point i, define two distances:

  • a(i) — the average distance from i to every other point in its own cluster ("how tight is my own group?")
  • b(i) — the average distance from i to every point in the nearest other cluster ("how close is the nearest rival group?")

A well-placed point should have a small a(i) and a large b(i). The silhouette score combines both into a single −1-to-+1 number:

s(i) = (b(i) − a(i)) / max(a(i), b(i))
If a(i) is much smaller than b(i) — tight in your own cluster, far from the nearest rival — what does s(i) come out close to?

+1. b(i)−a(i) is large and positive relative to the denominator, so the ratio approaches 1 — a great fit. If a(i)≈b(i) instead, s(i)→0 (sitting on a boundary between clusters); if a(i) exceeds b(i), s(i) goes negative — the point is actually closer, on average, to a different cluster than the one it was assigned to.

Worked example

Reuse the six-point clustering from §2: Cluster 1={P1(1,1),P2(1,2),P3(2,2)}, Cluster 2={P4(8,8),P5(8,9),P6(9,8)}. Compute the silhouette for P3=(2,2).

  1. a(P3) — average distance to its own clusterto P1 = √((2−1)²+(2−1)²) = √2 ≈ 1.414   to P2 = √((2−1)²+(2−2)²) = 1
    a(P3) = (1.414+1)/2 ≈ 1.207
  2. b(P3) — average distance to the nearest other clusterto P4 ≈ 8.485, to P5 ≈ 9.220, to P6 ≈ 9.220
    b(P3) = (8.485+9.220+9.220)/3 ≈ 8.975
  3. Silhouette scores(P3) = (8.975 − 1.207) / max(1.207, 8.975) = 7.768 / 8.975 ≈ 0.87

Near +1, as expected: this toy dataset's two clusters are extremely well separated. On messier real data, silhouette values typically sit much closer to 0, and negative values flag likely misassignment.

Python note

from sklearn.metrics import silhouette_score; silhouette_score(X, labels) computes the average silhouette over an entire dataset in one call, rather than looping over every point by hand.

The rest of the metric zoo

MetricWhat it captures
Silhouette CoefficientHow similar a point is to its own cluster vs. other clusters
Completeness ScoreWhether all same-true-label samples land in one cluster
Normalized Mutual Information (NMI)Alignment between clusters and true labels
Davies-Bouldin IndexWithin-cluster similarity vs. between-cluster dissimilarity
OthersCalinski-Harabasz, Rand Index, Adjusted Rand Index, Homogeneity Score

Completeness Score and NMI both require true labels to compare against — for validating a clustering method against known categories, not everyday unsupervised use. Silhouette and Davies-Bouldin only need the points and the cluster assignments themselves, which is why they're the ones you'll reach for most often on real exploratory work.

Rule

The metric that technically optimizes a clustering isn't necessarily the most useful one to report. Real value comes from profiling each cluster — dominant characteristics, mean/median/mode per feature, which variables actually differentiate the groups — and giving clusters meaningful names ("loyal customers," "support complainers") rather than just cluster IDs. A clustering with an excellent silhouette score but clusters you can't explain to a stakeholder in a sentence hasn't actually delivered the thing clustering exists to deliver.

Exercise 7 — Customer Segmentation with RFM + K-Means

IQR-trimmed, scaled, then K chosen via the elbow method (§3) before the final fit:

kmeans = KMeans(n_clusters=4, random_state=42) kmeans.fit(rfm_scaled)

Test Yourself

Retrieval practice — the single best-evidenced study technique there is.

Cover the answer, try to recall it from memory, then click to check. Getting it wrong and then reading the answer still strengthens the memory — skipping straight to the answer doesn't. Do this before your exam, not while reading for the first time.

In the module's analogy contrasting classification with clustering, what do isFraud(transaction) -> boolean and the missing equals()/hashCode() contract represent?

isFraud() represents classification — a method with a documented contract where someone already supplied correct answers for training examples. Clustering is like bucketing objects with no equals()/hashCode() contract at all, grouping purely by how alike their field values look, with no oracle checking your work.

In the six-point K-Means worked example (K=2, initial centroids C1=(1,1), C2=(8,8)), what were the two centroids after the single recompute step, and what was the total WCSS?

C1_new = (1.33, 1.67) and C2_new = (8.33, 8.33); total WCSS = 8/3 ≈ 2.67.

The module cites three K-Means runs on the same data and K but different random seeds. What WCSS values did they produce, and what does this demonstrate?

444.9, 349.7, and 451.4 — demonstrating that K-Means can converge to different local optima depending on initialization, which is why you should run multiple seeds and keep the lowest-inertia result.

In the elbow-method worked example, what were the WCSS values at K=1, K=2, and K=3, and why was K=2 identified as the elbow?

WCSS(1)≈142.83, WCSS(2)≈2.67, WCSS(3)≈1.83. K=2 is the elbow because the drop from K=1 to K=2 is over 140, while the drop from K=2 to K=3 is less than 1 — extra clusters beyond 2 just chip away at weak internal substructure.

In the "elongated cluster" worked example, why did K-Means assign the point (16,0) — the far end of elongated Group A — to Group B instead?

Group A's centroid was (8,0) and Group B's was (16,1.33); the squared distance from (16,0) to A's centroid was 64 versus only about 1.78 to B's centroid, so K-Means assigned it to the numerically nearer but wrong group, showing a single centroid poorly summarizes an elongated cluster.

For point P3=(2,2) in the silhouette worked example, what were a(P3), b(P3), and the resulting silhouette score s(P3)?

a(P3) ≈ 1.207 (average distance to P1 and P2), b(P3) ≈ 8.975 (average distance to P4, P5, P6), giving s(P3) = (8.975−1.207)/8.975 ≈ 0.87.

KMeans was fit with n_clusters=4. The churned segment stood out with a Recency of 244 days, far higher than the other three clusters.

Exam Drill

Same skills as Test Yourself, but in the exam's actual answer format.

Real exams rarely ask you to write a paragraph — they ask you to name a technique in a couple of words, reorder scrambled steps, pick every correct item from a list, or fill in one line of code. These drills train that exact shape of answer, not just the underlying concept.

Name it You want to pick a good K for K-Means by comparing how much your data's within-cluster spread improves versus what you'd see on purely random, structureless data. In ≤2 words, name this method.

Gap statistic. It measures your real WCSS decline against a simulated "no real structure" reference — the elbow method, by contrast, only ever looks at your data's own curve in isolation (§3).

Reorder Put these K-Means loop steps in order:
  1. A. Recompute each centroid as the mean of its assigned points
  2. B. Choose K and initialize K centroids
  3. C. Repeat until assignments stop changing
  4. D. Assign each point to its nearest centroid

B, D, A, C — initialize centroids → assign → recompute → repeat until converged (§2).

Select all Which of these can distort K-Means results?
  • (a) an unscaled feature with a much larger numeric range
  • (b) a single extreme outlier
  • (c) clusters that are elongated rather than round
  • (d) using more random-seed attempts (n_init)
  • (e) categorical features encoded as arbitrary integers

(a), (b), (c), (e). Each of these breaks an assumption K-Means relies on — comparable scales, outlier-free means, roughly spherical clusters, and numerically meaningful magnitude differences (§4). (d) is a fix for local optima, not a distortion.

Code Complete this to fit K-Means with 4 clusters, running 10 random initializations and keeping the best: KMeans(n_clusters=____, n_init=____, random_state=42)

n_clusters=4, n_init=10 — n_init is exactly the "try several seeds, keep the lowest-inertia run" fix from §2's Local Optima discussion, automated.

Compute Two points remain in a cluster: (2,2) and (4,4). Compute the centroid and this cluster's WCSS.

Centroid = mean = (3,3). Squared distance from (2,2): (2−3)²+(2−3)²=2. From (4,4): (4−3)²+(4−3)²=2. WCSS = 2+2 = 4 (§2).

Reorder Order the mathematical steps of the K-Means algorithm:
  1. Assign each data point to the cluster of its nearest centroid.
  2. Randomly initialize K centroids in the feature space.
  3. Recalculate the position of each centroid as the mean of its assigned points.
  4. Repeat distance calculations and mean updates until the centroids stop moving (convergence).
  5. Choose the number of clusters (K).
  6. Calculate the distance between every data point and every centroid.

5, 2, 6, 1, 3, 4 — Choose K → initialize centroids → calculate distances → assign points → update centroids → repeat until convergence.
