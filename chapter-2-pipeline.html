Framing the Problem

Before touching a model: what kind of analysis is this, and what does the data actually represent?

Matching the question to a technique

You have…You want to…Technique
Labelled data, target is a categoryPredict the category for new recordsClassification
Labelled data, target is a numberPredict the number for new recordsRegression
No labels, similar records existGroup similar recordsClustering
Transaction-style dataFind "items that occur together"Association analysis
No labels, rare deviations existFlag outliers / fraud / faultsAnomaly detection
Constraints + an objectiveFind the best feasible optionOptimization
Free-text dataUnderstand, mine, or generate languageText mining

Data representation isn't fixed

The same raw signal can be encoded numerically in several valid ways — the right one depends on the task, not the source format:

  • Text → TF-IDF (frequency-in-doc × rarity-across-corpus) or word embeddings (Word2Vec/GloVe place semantically similar words close together)
  • Images → raw pixel values
  • Graphs / molecules → nodes + edges, or learned node embeddings (Node2Vec)
  • Audio → raw waveform or a spectrogram (frequency content over time)

Sample size: bigger isn't automatically better

More data reduces random noise, increases statistical power, and helps models generalize instead of memorizing. But it does not fix bias or poor data quality — and it can make tiny, irrelevant effects look statistically significant. Data quality and representativeness matter as much as row count.

Rule

Always split into train / validation / test before modelling. Train fits the model, validation tunes hyperparameters, test gives an honest, untouched read on generalization.

2

Preprocessing

Engineer features → handle missing data → handle imbalance → scale → reduce dimensions. Order matters; every step below is fit on train only.

Feature engineering

  • Creation — derive new signal, e.g. speed from time + distance
  • Combining — interaction terms (x·y, x²) e.g. income ÷ hours → income-per-hour
  • Aggregation — mean/sum/count over a group
  • Datetime — extract hour, weekday, season from a timestamp
  • Text — word counts, sentiment, embeddings

Good feature engineering leans on domain knowledge — e.g. an ECG signal becomes useful only once P/Q/R/S/T peak intervals are extracted from the raw waveform.

Encoding categorical variables

Most algorithms need numbers. Label encoding (Red=0, Green=1, Blue=2) invents a false ordinal relationship — the model reads "Blue is 2× Green," which corrupts anything doing arithmetic on inputs (linear/logistic regression, k-NN, neural nets). One-hot encoding avoids this by giving each category its own binary column.

Watch out

After one-hot encoding, drop one of the new columns. Keeping all of them is redundant (the last category is implied by all-zeros elsewhere) and can introduce multicollinearity.

Binning groups a numeric range into buckets (age 0–1 = infant, 1–3 = toddler, …), effectively converting numeric → categorical. The trade-off: a model treats 1 and 1.5 as different (different bins) but 6 and 10 as identical (same bin).

Missing data

Missingness shows up as missing values in a table, or as missing categories entirely — the classic case being survivorship bias: WWII engineers who reinforced only the bullet holes visible on planes that returned were looking at the wrong data — the planes hit in the unmarked zones never made it back. Always ask what's absent from the sample, not just what's null in a cell.

StrategyWhen
Ignore the recordMissingness is rare and random
Add an "is-missing" indicator columnMissingness itself might be predictive
Use a model robust to missing valuesSome tree-based libraries handle it natively
Impute — constant, mean/median, class-wise mean/median, or model-based (predict the missing value from other columns)Default fallback; remember it's an educated guess

Imbalanced classes

When one class dominates: (1) use a model/objective suited to imbalance, (2) resample — downsample the majority or upsample/augment the minority, (3) evaluate with metrics that don't reward "always predict the majority" (see §4).

Feature scaling & normalization

Distance-based methods (k-NN, SVM, clustering) and gradient-based training (neural nets) implicitly let the largest-magnitude feature dominate. A 100 m² gap in house size will swamp a 1-room gap in room count unless both are rescaled to comparable ranges.

MethodWhat it doesTypical use
Min-MaxRescales to [0, 1]Neural nets, image data
Z-score (standardization)Centers to mean 0, std 1Most general-purpose ML
Robust scalingUses median & IQRHeavy-tailed / outlier-prone features
Z-scorex_normalized = (x − μ) / σ
Rule

Fit the scaler on training data only. The resulting μ/σ (or min/max) are part of the model — save them and re-apply the identical transform to test and production data. Never re-fit on test data.

Dimensionality reduction vs. feature selection

Feature selection drops columns unchanged. Dimensionality reduction transforms many features into fewer derived ones (1000 → 10), via linear methods (PCA, LDA, ICA) or non-linear methods (t-SNE, UMAP, autoencoders) — detailed next.

Motivation is twofold: the curse of dimensionality (classifier performance peaks, then degrades as features keep growing without more samples — the space gets too sparse to learn from), and visualization of otherwise unplottable data (e.g. scRNA-seq: ~100,000 cells × ~30,000 genes, reduced to 2–10 dimensions).

3

PCA & t-SNE

Two dimensionality-reduction workhorses with opposite philosophies — one linear and global, one non-linear and local.

PCA — Principal Component Analysis

Finds new orthogonal axes ("principal components") ranked by how much variance they capture, then rotates the data onto them. Deterministic and linear.

  1. Standardize/center the data (mean → 0) so PCA captures shape, not location
  2. Compute the covariance matrix, then its eigenvectors (directions) and eigenvalues (variance captured per direction)
  3. Sort by eigenvalue, descending — PC1 always captures the most variance possible, PC2 the most of what's left, etc.
  4. Project the data onto the top-k components and discard the rest
CovarianceCov(x, y) = 1/(n−1) · Σ (xᵢ − x̄)(yᵢ − ȳ) Projection (loadings)PCᵢ = X · vᵢ = a₁x₁ + a₂x₂ + … + a_d x_d

The loading weights (a₁, a₂, …) reveal which original features drive a component — useful for explaining what a PC actually means. PCA is excellent at linear correlation and preserves global structure, but if the data lies on a curved manifold, PCA flattens it onto a plane and destroys the real geometry.

t-SNE — t-Distributed Stochastic Neighbor Embedding

Built specifically to visualize high-dimensional data by preserving local neighborhoods, not global distances. Non-linear and stochastic.

Similarity in high-D (Gaussian, then symmetrized)P(i|j) = exp(−‖xᵢ−xⱼ‖² / 2σᵢ²) / Σ_{k≠i} exp(−‖xᵢ−xₖ‖² / 2σᵢ²) Pᵢⱼ = (P(j|i) + P(i|j)) / 2N Minimize via gradient descentKL(P ‖ Q) = Σ pᵢⱼ log(pᵢⱼ / qᵢⱼ)

Points are scattered randomly in low-D, then iteratively attract or repel each other until the low-D similarity distribution (t-distributed, Q) matches the high-D one (Gaussian, P) as closely as possible.

Perplexity (a hyperparameter) sets the effective neighborhood size and controls the local/global trade-off — too low fragments real clusters, too high merges distinct ones into a blob. It has to be tuned per dataset.

UMAP targets the same visualization goal as t-SNE — generally faster and better at preserving some global structure alongside the local — worth reaching for once PCA and t-SNE feel comfortable.

Tip

They're complementary, not competing: running PCA first (to denoise / speed up), then t-SNE or UMAP on the PCA output, is a common combo.

Validating & Evaluating Models

A model is only as trustworthy as the metric used to judge it — and the obvious metric is often the wrong one.

The confusion matrix

Predicted positivePredicted negative
Actually positiveTrue Positive (TP)False Negative (FN)
Actually negativeFalse Positive (FP)True Negative (TN)

Precision

Of everything flagged positive, how much was right?

TP / (TP + FP)

Recall (Sensitivity)

Of everything actually positive, how much did we catch?

TP / (TP + FN)

Specificity

Of everything actually negative, how much did we catch?

TN / (TN + FP)

Accuracy

Of everything, how much was classified correctly?

(TP+TN) / (TP+TN+FP+FN)
Watch out

A classifier that predicts "positive" for everyone scores 100% recall. One that predicts "negative" for everyone scores 100% specificity — and, if 98% of the data really is negative, 98% accuracy too. None of that means the model is useful.

The base-rate trap

Rare disease, prevalence 0.1%. Test: 99% true-positive rate, 2% false-positive rate. Someone tests positive — what's P(disease)? Bayes' rule, not intuition:

P(D|P) = P(P|D)·P(D) / [P(P|D)·P(D) + P(P|H)·P(H)] = (.99 × .001) / (.99 × .001 + .02 × .999) ≈ 4.7%

Even with a "99% accurate" test, most positives are false positives — because healthy people vastly outnumber sick ones. Base rates dominate when the condition is rare.

F1 score

The harmonic mean of precision and recall — preferred when the positive class is rare and both false positives and false negatives carry real cost.

F1 = 2 · Precision · Recall / (Precision + Recall)

ROC / AUC

Plots True-Positive Rate against False-Positive Rate across every possible decision threshold, instead of committing to one. The diagonal is a random classifier; the closer the curve hugs the top-left corner, the better. Lets you pick the threshold that matches how much your application tolerates false alarms vs. missed detections.

Rule

The training cost function is only a proxy for the real-world objective. Choose evaluation metrics deliberately — they should reflect which errors actually cost you, and account for class imbalance.

5

Modelling & Choosing a Model

Fitting is iterative; the best-scoring model on paper is not automatically the right one to ship.

Training = minimizing a cost function

The learning algorithm repeatedly compares model output against ground truth, computes an error (the cost/objective function), and uses that error to nudge the model's parameters — forward pass, compute loss, backward pass, repeat.

Overfitting

Low bias, high variance. The model memorizes training noise — a jagged decision boundary that fits training points perfectly but generalizes poorly.

Underfitting

High bias, low variance. The model is too simple to capture real structure — both train and validation error stay high.

Hyperparameters vs. model parameters

Model parametersHyperparameters
Set byLearned during trainingChosen before training
PurposeDefine the model's learned behaviorControl the learning process itself
ExamplesWeights, biasesLearning rate, epochs, tree depth, perplexity
Tuned viaOptimization (gradient descent, …)Search / validation (grid, random, …)

"Best score" ≠ "most suitable"

Alongside raw performance, weigh:

  • Generalizability — avoids overfitting, holds up on unseen data
  • Simplicity & maintainability — easier to debug, update, deploy
  • Speed & efficiency — meets latency/resource constraints
  • Interpretability — often non-negotiable in healthcare, finance, law
  • Stability & reproducibility — consistent across data variations

Choosing a model is a match between data properties (feature count, sample size, input/output format) and model properties (accuracy, simplicity, interpretability, speed) — closer to adjusting a recipe while cooking than picking one in advance.

Quick decision path

QuestionThen look at
< 50 samples?Get more data before modelling
No labels — just exploring structure?Dimensionality reduction (PCA / UMAP)
No labels — grouping needed, category count known?K-Means; unknown count → Mean-Shift / GMM
Labelled, predicting a category?Naive Bayes / linear SVC (small data) → k-NN / ensembles / SGD (larger data)
