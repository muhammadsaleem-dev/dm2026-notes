Module 2

The Data Mining Pipeline

20 pts subtotal · 3 questions
📖 Module 2 Bootcamp Core Notes & Theory Cheat Sheet Click to expand refresher before solving

PCA — linear, deterministic dimensionality reduction

  • Use PCA when the data is high-dimensional, relationships are mostly linear, and you care about
preserving global structure and interpretability of components.
  • PCA finds new orthogonal axes ("principal components") ranked by how much variance they capture, then
rotates the data onto them — most of the real information collapses into the first handful of axes.
  • Deterministic: run it twice on the same data, get the identical answer — unlike t-SNE, which is
stochastic and only preserves local neighborhoods, not global structure.

(Module 2 §3)

Identifying numerical columns + train_test_split

  • Dataframe.select_dtypes(include=np.number).columns returns exactly the numeric columns of a
DataFrame — the standard way to separate numeric from categorical before scaling/encoding.
  • Always split into train / validation / test before modelling; the test set stays untouched until
the very end.
  • train_test_split(X, y, test_size=0.3, random_state=RANDOM_STATE) — fixing random_state makes the
"random" split reproducible.

(Module 2 §1)

MinMaxScaler — rescaling to a fixed range

  • Min-Max scaling rescales every value to [0, 1]: x_scaled = (x - min) / (max - min). Common for
neural nets and image data.
  • Contrast with Z-score (standardization), which centers to mean 0, std 1 — the more general-purpose
default. Min-Max is preferred when you need values in a bounded range, not just comparable scale.
  • Fit the scaler on training data only, then apply the identical fitted transform to test data.
Never re-fit on test data — the min/max learned from training are part of the model.

(Module 2 §2)

The NN training loop — forward/backward pass ordering

Define architecture → initialize weights/biases → repeat:

  • Forward pass — push the input through every layer to get a prediction.
  • Compute cost — how wrong was that prediction?
  • Backpropagation — compute how much each weight needs to change, moving backward from output to input.
  • Update parameters, then monitor progress (print train/test error).

…until a stopping condition (enough epochs, or the loss stops improving).

(Module 5 §5 — ① forward propagation ② backpropagation)

LLM & RAG Pipeline

25 pts subtotal · 5 questions
📖 Module 6 Bootcamp Core Notes & Theory Cheat Sheet Click to expand refresher before solving

Semantic search & cosine similarity

  • Once every chunk and query is embedded, "search" becomes geometry: find the nearest stored points.
  • Cosine similarity measures the angle between two vectors, ignoring magnitude — robust to
incidental differences like passage length. It's the standard mathematical method for ranking chunk relevance in the semantic-search step of a RAG pipeline.

(Module 6 §4)

Vocabulary size & greedy decoding

  • The LLM's output layer is a softmax over the entire vocabulary — its size equals vocabulary size,
not embedding dimension, not context length. So vocab_size = len(logits).
  • Greedy decoding — always pick argmax(logits). Deterministic: same input, same output every time —
safe and reproducible, but repetitive.

(Module 6 §1–2)

Temperature — reshaping the distribution before sampling

  • Temperature reshapes the probability distribution before sampling, instead of always taking the single
most likely token: p(zᵢ) = exp(zᵢ/T) / Σⱼ exp(zⱼ/T).
  • Dividing every logit by T before exponentiating compresses or stretches the gaps between logits.
Softmax is monotonic — dividing by T never changes which token has the highest score, only how much more likely it is relative to the rest.
  • Low T (< 1) sharpens the distribution toward the front-runner — more deterministic, less varied.
High T (> 1) flattens it — every token becomes more competitive, more random/creative. T = 1 leaves the raw distribution untouched.

(Module 6 §2)

def right_function(logits, temperature):
    logits = np.array(logits)
    # YOUR CODE HERE
    # Hint: Apply softmax with temperature scaling: exp(logits/T) / sum(exp(logits/T))
    # [SOLUTION]: Scale logits by temperature and apply softmax
    scaled_logits = logits / temperature
    exp_logits = np.exp(scaled_logits - np.max(scaled_logits))
    probabilities = exp_logits / np.sum(exp_logits)

    return np.round(probabilities, 3).tolist()

# compute the probabilities
probs_T05 = right_function([2.0, 1.0, 0.5, 0.01, 3, 2, 1.5], 0.5)
probs_T1 = right_function([2.0, 1.0, 0.5, 0.01, 3, 2, 1.5], 1)
probs_T3 = right_function([2.0, 1.0, 0.5, 0.01, 3, 2, 1.5], 3)

print("T = 0.5:", probs_T05)
print("T = 1.0:", probs_T1)

Module 7

Explainability & Causality

25 pts subtotal · 4 questions
📖 Module 7 Bootcamp Core Notes & Theory Cheat Sheet Click to expand refresher before solving

Permutation importance — breaking a feature to measure it

  • Insight: if a feature matters, destroying its information should hurt performance; if it's
irrelevant, scrambling it shouldn't change anything.
  • Procedure: train, measure baseline score → shuffle one feature's column → re-evaluate → importance =
baseline − new score → repeat K times per feature, average, rank.
  • Model-agnostic — never looks inside the model, only shuffles inputs and reads outputs. This is
exactly the technique to reach for when asked "how do I find out which features/risk factors actually drive this model's predictions?"

(Module 7 §3)

PDP / SHAP for directional impact

  • Permutation importance tells you how much a feature matters, but not which direction it pushes the
prediction. To show whether a feature pushes predictions up or down, use:
  • Partial Dependence Plots (PDP) — show the model's average predicted outcome as one feature varies,
holding others fixed, directly visualizing the direction of effect.
  • SHAP summary/beeswarm plots — dot position = impact on the prediction, color = the feature's
actual value, revealing direction and magnitude together for every instance.

(Module 7 §4)

Choosing a scoring function for permutation importance

  • The scoring argument must satisfy "higher is better." Classification metrics (accuracy, F1) already
work that way.
  • A regression target (like Remaining Useful Life, measured in continuous operating hours) needs a
negated error metric instead — scoring='neg_root_mean_squared_error' or 'neg_mean_absolute_error' — since raw RMSE/MAE are "lower is better," and negating flips that so the same "baseline − shuffled" subtraction still works correctly.

(Module 7 §3)
