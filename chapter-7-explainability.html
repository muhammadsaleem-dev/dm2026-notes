Explainability & Causality

Condensed reference

Two different questions that get conflated constantly: "what did the model use?" (explainability) and "what actually changes the outcome?" (causality).

1

Why Explainability Matters

Different stakeholders need different explanations from the same model.

Stakeholder (loan approval)Their question
Domain user (loan officer)"Why is this client risky? Can I trust this model?"
Developer"Why does the model behave this way? How do I fix an error?"
Auditor"Are minority groups disproportionately denied? Is it using appropriate factors?"
End user"Why was my loan denied?"

Accuracy vs. explainability trade-off: a decision tree is highly interpretable but often less accurate; a neural network is far less interpretable but often more accurate. The right balance depends on ROI and compliance requirements, not just raw performance.

Rule

Explainability matters most when decisions affect people's lives (healthcare, finance, justice), when regulation demands transparency, or when trust is the product. It matters less for low-stakes decisions where speed/accuracy dominate.

In a decision tree, the order of splits already reveals feature importance — the first split is the most discriminating feature. In logistic regression, ŷ = σ(wᵀx + b), the learned weights are each feature's contribution. A random forest is built from inherently-explainable trees, yet the ensemble's combined decision is not — which is exactly why post-hoc methods exist.

3

Permutation Feature Importance

If a feature matters, breaking it should hurt performance.

  1. Train the model; measure baseline performance s (e.g. 90% accuracy).
  2. Randomly shuffle one feature's column only, leaving everything else untouched.
  3. Re-evaluate → new score (e.g. 78%).
  4. Importance = baseline − new score (90% − 78% = 12%).
  5. Repeat K times per feature and average, to smooth out random variation; rank all features by their drop.

Worked ranking: Age 12% > Income 7% > Balance 4% > Region 1% > Gender 0%.

Quiz

If shuffling a feature improves performance, does that mean the feature is useless? No — a negative importance means the model does better once that feature's information is destroyed, which points to noise, overfitting, redundancy, or a harmful learned dependency.

Pros: model-agnostic, simple to implement and explain. Cons: correlated features can mask each other's importance; expensive with many features; unstable on small datasets.

4

Shapley Values (SHAP)

Borrowed from game theory: features are "players," the prediction is the "payout" to split fairly.

For feature i, look at every possible subset S of the other features, and compute the marginal contribution of adding i to that subset: f(S∪{i}) − f(S). Average this over all possible feature orderings, weighted so no ordering biases the result:

φᵢ(v) = Σ_{S⊆N\{i}} [ |S|!·(n−|S|−1)! / n! ] · ( v(S∪{i}) − v(S) )

Features that consistently add value across orderings score high; features that only sometimes help score proportionally less.

Reading a SHAP output: final prediction = base value + Σ SHAP values. A summary/bar plot (global) ranks features by mean |SHAP value|. A beeswarm plot (local, per-instance) shows every data point's SHAP value (impact) and its actual feature value (color) — revealing both magnitude and direction together.

Key warning

SHAP values do not reflect causality. A high-importance feature (e.g. Titanic "Fare") is useful for prediction, but may just be capturing information about a different real cause — it doesn't mean changing that feature would change the outcome. Predictive importance ≠ actionability.

5

Causality: Beyond Correlation

Explainability says what the model used. Causality asks what would actually change the outcome.

Causal analysis studies cause-and-effect directly — via causal inference (does X cause Y?), counterfactual analysis ("what if?"), and interventions (simulate an action, observe the effect). It matters for decisions you actually intend to act on: treatment choices, policy changes.

Confounders — the trap explainability alone can't see

  • Umbrellas & accidents: a model finds umbrella ownership predicts traffic accidents. The real cause is rain, which drives both. Handing out umbrellas would not reduce accidents.
  • Titanic — Sex: explainability ranks "sex" as the top predictor of survival. The real cause was the unrecorded "women and children first" evacuation policy — sex didn't cause survival, it correlated with who got lifeboat access.
  • Titanic — Fare: explainability ranks fare as important, but higher fare really just correlated with passenger class — cabins closer to lifeboats, faster crew assistance.
