Framing: Neural Nets as Generalized Regression

"Neural networks are the generalization of linear regression."

If you've never trained a model before, the natural question is: how does a program "learn" a function instead of being told one? The answer this whole module builds toward is reassuringly mechanical — a model is a small number of adjustable numbers (its parameters), a cost function that scores how wrong the model currently is, and a search procedure that nudges the parameters to make that score smaller. Everything else — logistic regression, neural networks, backpropagation — is a variation on that one idea, applied to bigger and more expressive families of functions.

Start with the smallest possible learning unit: a single artificial neuron, also called a perceptron. Structurally it does three things in sequence — take a set of inputs, combine them into one number via a weighted sum Σwᵢxᵢ + b, then pass that number through a non-linear "squashing" function φ(·) to produce an output. If that sounds familiar, it should: it's exactly the computation logistic regression performs (§4). That's the reveal the whole module is built around: a perceptron is logistic regression; a neural network is many logistic-regression units stacked in layers and chained together. Once that clicks, a lot of what looks like "deep learning magic" becomes just "logistic regression, repeated with feeling."

It's worth placing this next to the other ways of getting a computer to do a task, since they differ only in where the rules/features come from:

  • Classical programming — a human studies the problem and writes explicit rules by hand.
  • Machine learning — a human still hand-designs the features (e.g. "tumor radius," "tumor texture"), but the model learns the weights that combine them.
  • Deep learning — the model learns the features themselves, directly from raw inputs (pixels, characters, sensor readings), with no hand-engineering step at all.

All three follow the same loop: study problem → (write rules | train on hand-designed features | train on self-learned features) → evaluate → analyze errors → repeat. The only thing that moves as you go from classical programming to deep learning is which stage of that pipeline is automated.

Vocabulary you'll need immediately: a network with a single hidden layer is informally "non-deep" — it's really just one logistic-regression unit feeding another. Deep learning conventionally starts at three or more hidden layers, and production networks often stack hundreds. Depth is what lets a network build a hierarchy of learned features rather than a single flat transformation — a theme §5 returns to with the image-recognition example (edges → contours → parts → whole object).

2

Linear Regression, Properly

Every neuron's math starts here.

Before you can understand a neuron, you need to understand the piece of math sitting inside it: a linear model and how you measure whether it's any good. No non-linearity, no probabilities — every neuron's math starts here and adds complexity on top.

Modelŷ = Xω + b

X is your matrix of input features, ω a vector of weights (one per feature), b a scalar bias. Together θ = (ω, b) is the full set of numbers the learning algorithm is allowed to adjust — "fitting the model" means searching for the θ that makes ŷ track y as closely as possible.

AssumptionMeaning
LinearityRelationship between X and Y is linear
IndependenceObservations are independent
HomoscedasticityConstant variance of residuals across predicted levels
NormalityErrors are normally distributed
No multicollinearityPredictors aren't highly correlated with each other

Violations of these aren't requirements for the code to run — they're exactly why a regression that "runs fine" can still give misleading coefficients (a concrete example appears in the Sprint Exercises, where near-perfectly correlated features blow up the coefficients into meaningless enormous numbers).

Measuring wrongness: the cost function

Once you have a candidate θ, you need a single number saying "how bad is this θ." The standard choice for regression is Mean Squared Error (MSE):

J(θ) = (1/2M) · Σᵢ (y⁽ⁱ⁾ − ŷ⁽ⁱ⁾)²

For every data point, take the difference between true and predicted value (the residual), square it, add up all the squares, divide by 2M (the "2" cancels out neatly once you take a derivative in §3 — it doesn't change where the minimum is, only tidies the gradient formula).

Why squared error rather than absolute error? Squaring makes the cost differentiable everywhere, and — more importantly — makes the penalty grow faster the further off you are: being off by 4 costs 16× as much as being off by 1, not just 4×. That steep, curved shape is precisely what gradient-based search in §3 exploits to know not just which direction to move but how urgently. Brute-force search — trying a grid of candidate θ values — ignores that curvature and becomes hopeless once θ has more than a couple of dimensions (imagine gridding 30,000 weights).

Worked example

A tiny invented dataset, chosen so the "true" relationship is easy to see: (x,y) = (1,3), (2,5), (3,7), following y=2x+1 exactly. Suppose we haven't found that relationship yet — we're testing a candidate guess θ=(ω=1.5, b=1). Illustrative toy numbers, not the real dataset from the exercises.

Predictions using ŷ=ωx+b: x=1→ŷ=2.5, x=2→ŷ=4.0, x=3→ŷ=5.5.

Sum of squared residuals = 3.5. With M=3, 2M=6: J(θ) = 3.5/6 ≈ 0.583. If we'd tried ω=2, b=1 (the actual generating relationship), every residual would be 0, and J would be 0 — the true global minimum. §3 is how you find that θ automatically, without already knowing the answer.

Other linear-model variants

MethodIdea
Polynomial regressionAdds x², x³ terms — non-linear in x, still linear in the parameters
Ridge (L2)Penalizes Σwⱼ² — fights multicollinearity/overfitting, shrinks weights but rarely to zero
Lasso (L1)Can shrink weights to exactly zero → automatic feature selection

All three penalized variants add an extra term to J(θ) that punishes large weights, changing what "minimizing J" means without changing the gradient-descent machinery used to minimize it. Ridge and Lasso become central to the Sprint Exercises' heating-load problem, where ordinary linear regression's coefficients blow up due to near-duplicate features.

3

Gradient Descent

The one optimization algorithm everything else in this module reuses.

You now have a way to score any candidate θ (§2's MSE). What you don't have is a way to search for a good one without brute-forcing every possibility. Gradient descent does this, and it is the single optimization procedure that logistic regression, neural-network training, and backpropagation all reuse without modification to the core idea.

Picture the cost function J(θ) as hilly terrain, where your current θ is a location and altitude is how bad that θ is. You're standing in fog, and you want to walk downhill. At any location you can feel which direction is steepest and how steep it is — that's the gradient: the direction of steepest ascent, and how fast the function is changing in that direction. To go down, step in the exact opposite direction, taking a bigger step when the ground is steep and a smaller one as it flattens near the minimum. That's the entire algorithm.

  1. Pick a random initial θ and a learning rate α.
  2. Repeat until convergence: θⱼ ← θⱼ − α · ∂J(θ)/∂θⱼ for every parameter j.

Each parameter gets its own partial derivative — its own "which way is downhill for this one knob" — updated independently. For linear regression + MSE, the chain rule gives closed-form expressions:

∂J/∂b = −(1/M) Σ (y⁽ⁱ⁾ − (ωx⁽ⁱ⁾+b)) ∂J/∂ω = −(1/M) Σ (y⁽ⁱ⁾ − (ωx⁽ⁱ⁾+b)) · xᵀ⁽ⁱ⁾

(ωx⁽ⁱ⁾+b) is just ŷ⁽ⁱ⁾ — so both formulas are really "average residual" and "average residual weighted by x," with a minus sign from differentiating a squared-error term.

Worked example

Continuing the toy dataset from §2: (x,y)=(1,3),(2,5),(3,7), current guess ω=1.5, b=1, learning rate α=0.1. Small invented numbers, not the real dataset.

Residuals from §2: 0.5, 1.0, 1.5.

Bias gradient: ∂J/∂b = −(1/3)·(0.5+1.0+1.5) = −(1/3)·3.0 = −1.0.

Weight gradient: ∂J/∂ω = −(1/3)·(0.5×1+1.0×2+1.5×3) = −(1/3)·7.0 ≈ −2.333.

Update: b_new = 1 − 0.1×(−1.0) = 1.1. ω_new = 1.5 − 0.1×(−2.333) ≈ 1.733.

ω moved toward the true value of 2 (the model was underestimating the slope), while b moved slightly away from its true value of 1 — not a bug. Gradient descent doesn't optimize each parameter's individual correctness in isolation; it moves the whole parameter vector in the direction that reduces total cost fastest given the current errors, which are dominated by the wrong slope. Later iterations correct the bias too — this is why the algorithm needs to repeat: one step rarely lands you at the minimum.

For a convex cost surface — linear regression with MSE has exactly one basin, no false minima — this walk is guaranteed to reach the global minimum eventually. The caveat: convexity guarantees the destination exists, not that any learning rate gets you there. Too large an α can still overshoot and diverge even on a convex surface.

Learning rate αEffect
Too lowMany tiny steps, slow convergence
Just rightEfficient convergence
Too highOvershoots, oscillates, can diverge
4

Logistic Regression → One Neuron

Running example: predicting malignant vs. benign from tumor measurements.

Linear regression predicts an unbounded real number — fine for "how many degrees of heating load," useless for "is this tumor malignant." For that you want a prediction that behaves like a probability: a number between 0 and 1. Logistic regression bolts a probability-producing step onto the linear machinery from §2–3 — and, as promised in §1, it's also exactly the computation a single neuron performs.

The raw weighted sum z = wᵀx + b can be any real number. The sigmoid function squashes it into (0,1): very negative inputs map close to 0, very positive close to 1, and 0 maps to exactly 0.5.

z = wᵀx + b ŷ = σ(z) = 1 / (1 + e^−(wᵀx+b))

Converting the probability ŷ to a hard decision is just picking a threshold — 0.5 by default, but movable if false negatives and false positives cost differently.

Worked example

A made-up model has weights w=[0.5, −0.3], bias b=0.1, over two features. A patient has x=[2,1], true label y=1 (malignant). Invented toy example, not real clinical data.

z = 0.5×2 + (−0.3)×1 + 0.1 = 1.0 − 0.3 + 0.1 = 0.8. With e⁻⁰·⁸≈0.449: ŷ = σ(0.8) = 1/(1+0.449) = 1/1.449 ≈ 0.690 — "69% probability malignant." At a 0.5 threshold that rounds to label 1, matching the true label — but the probability is the actual output; the hard label is a downstream decision.

Measuring wrongness for probabilities: cross-entropy

MSE isn't the right tool here — plugging a sigmoid output into squared error gives a non-convex cost surface, and gradient descent can get stuck. There's also a more intuitive reason: squared error treats "predicted 0.9, true 1" and "predicted 0.1, true 1" as differing only by degree, but a confidently wrong prediction should be penalized much more harshly. A logarithmic penalty does exactly that — as a predicted probability for the correct class approaches 0, −log(·) shoots toward infinity. This is binary cross-entropy:

J(ω,b) = −(1/M) Σᵢ [ y⁽ⁱ⁾ log(ŷ⁽ⁱ⁾) + (1−y⁽ⁱ⁾) log(1−ŷ⁽ⁱ⁾) ]

For any single point, only one bracketed term is ever active, since y is 0 or 1: if y=1 you're left with −log(ŷ); if y=0, −log(1−ŷ). Per-point, cross-entropy is "negative log of the probability the model assigned to the actual correct answer."

Worked example

Continuing the patient: ŷ=0.690, y=1. Since y=1, only the first term survives: J = −log(0.690) ≈ 0.371. If the model had instead confidently output ŷ=0.05 for this true-positive case: J = −log(0.05) ≈ 3.0 — roughly eight times worse for a "similar-looking" miss, exactly the confident-wrong-answers-hurt-more behavior we wanted.

Differentiating J with respect to weights via the chain rule, using σ′(x)=σ(x)(1−σ(x)), all the log/exp terms cancel:

∂J/∂ω = (1/M) Σ (ŷ⁽ⁱ⁾ − y⁽ⁱ⁾) · xᵀ⁽ⁱ⁾

This is the same shape as the linear-regression gradient from §3 (average error, weighted by x) — not a coincidence, and the detail that lets §5 reuse one uniform update rule across every layer of a network.

Worked example

Same patient (ŷ=0.690, y=1, x=[2,1]), with M=1: ∂J/∂w = (0.690−1)×[2,1] = (−0.310)×[2,1] = [−0.620, −0.310], and ∂J/∂b = ŷ−y = −0.310. Feed these into the exact same gradient-descent update rule from §3 and you're training a neuron. There is no separate "logistic regression algorithm" beyond swapping in this gradient.

More than two classes

Real classification problems often have more than two labels — the CIFAR-10 image task in the Sprint Exercises has ten. Two standard extensions:

  • One-vs-Rest (OvR) — train one separate binary model per class, then pick whichever is most confident.
  • Softmax regression — direct generalization of sigmoid to many classes: softmax(zᵢ) = e^zᵢ / Σⱼ e^zⱼ, turning a whole vector of raw scores into a probability distribution summing to 1.
Worked example

Raw class scores z=[1.30, 5.10, 2.20, 0.70, 1.10]. Exponentiate: e^1.30≈3.67, e^5.10≈164.02, e^2.20≈9.03, e^0.70≈2.01, e^1.10≈3.00. Sum ≈ 181.73. Divide each by the sum: softmax(z) ≈ [0.02, 0.90, 0.05, 0.01, 0.02] — a clean distribution dominated by class 2, summing to 1.00. This is exactly the Dense(10, softmax) layer in the CIFAR-10 exercise's output: ten raw scores in, ten class probabilities out.

Why logistic regression isn't enough

LimitationDescription
Linear boundaries onlyFails on non-linearly-separable data
Limited feature interactionDoesn't capture interactions unless manually engineered
Limited capacityStruggles with complex tasks (image/audio classification)

The "linear boundaries only" row matters most: a single neuron's decision boundary is always a flat hyperplane, no matter how you tune w and b. If your classes can't be separated by a straight line, no amount of retraining a single unit fixes that. The fix isn't a better neuron — it's more than one, arranged so their combined output can bend into curved, complex boundaries. That's §5.

5

Building the Network

Each hidden unit is now called a neuron — a mini logistic regression whose output feeds the next layer.

A single neuron caps out at drawing straight lines. Stack several into a hidden layer, feed that layer's outputs into another neuron (or layer), and the combined function can represent boundaries of essentially arbitrary shape. Each hidden unit is nothing more exotic than the mini logistic-regression unit from §4 — weighted sum, then activation — except its output isn't the final answer; it's an input to the next layer.

Chaining layers builds a hierarchy of learned transformations. The canonical illustration is image recognition: the first hidden layer might learn to detect edges, the next combines edges into contours, the next combines contours into object parts, and the final layer combines parts into whole-object identity — with no human ever writing an "edge detector" by hand. Nobody designs this hierarchy explicitly; it falls out of training because it happens to be an effective way to reduce the cost function.

Python note

This layer-by-layer structure is literally how you build a network in Keras: keras.Sequential([...]) lists layers in order, and Dense(n, activation=...) is a "fully-connected" layer of n neurons, each taking every output of the previous layer as input. A two-layer network would be Sequential([Dense(hidden_units, activation='sigmoid'), Dense(output_units, activation='sigmoid')]) — the code mirrors the layer-by-layer math almost line for line.

Forward propagation

Forward propagation is just the name for "running the network": push an input through layer 1's weighted-sum-then-activation, push that result through layer 2's, and so on to the output. It's the nested-function evaluation the "neuron feeds into neuron" picture already implies:

z^[1] = W^[1]x + b^[1], a^[1] = g^[1](z^[1]) z^[2] = W^[2]a^[1] + b^[2], a^[2] = g^[2](z^[2]) = ŷ ŷ = g^[2]( W^[2] · g^[1](W^[1]x + b^[1]) + b^[2] )

Layer 1 takes raw input x, computes z^[1], applies g^[1] to get a^[1]. Layer 2 treats a^[1] exactly the way layer 1 treated x — its own z^[2], its own g^[2] — and its output is ŷ. The bracketed superscript is purely a layer index, unrelated to exponents.

Worked example

2 inputs, 1 hidden neuron, 1 output neuron, both sigmoid. Small invented weights, purely to make the arithmetic easy — not values from real training.

Inputs x=[1.0, 0.5]. Hidden-layer: W^[1]=[0.4,−0.2], b^[1]=0.1.

z^[1] = 0.4×1.0 + (−0.2)×0.5 + 0.1 = 0.4−0.1+0.1 = 0.4. With e⁻⁰·⁴≈0.670: a^[1] = σ(0.4) = 1/1.670 ≈ 0.599 — the hidden neuron's output, now becoming input to the output layer.

Output-layer weight: W^[2]=0.7, b^[2]=−0.2. z^[2] = 0.7×0.599 + (−0.2) = 0.419−0.2 = 0.219. With e⁻⁰·²¹⁹≈0.803: a^[2] = σ(0.219) = 1/1.803 ≈ 0.555.

So ŷ = a^[2] ≈ 0.555 — the entire forward pass, two weighted sums and two sigmoid evaluations, chained. Everything after this — cost, gradients, updates — builds on this one computed number.

Backpropagation

Forward propagation gets you a prediction and, via a cost function, a number saying how wrong it was. The remaining problem: a real network might have thousands of weights across many layers, and you need ∂J/∂θ for every one to run gradient descent. Recomputing each independently would be wasteful — many share large chunks of the same chain-rule computation.

Backpropagation avoids that waste: still just the chain rule, still just gradient descent, but organized to compute the last layer's gradients first, then reuse pieces of that computation for the layer before it, and so on backward to the first layer. Forward propagation pushes data forward from input to output; backpropagation pushes the error signal backward from output to input, layer by layer, updating every parameter it passes.

W^[2] := W^[2] − η∇_W[2]J, b^[2] := b^[2] − η∇_b[2]J W^[1] := W^[1] − η∇_W[1]J, b^[1] := b^[1] − η∇_b[1]J

(η is the same thing as α in §3.) At the output layer, the gradient has a strikingly simple closed form — and you've already derived the key piece of it, back in §4's logistic-regression gradient:

∇_z[2]J = ŷ − y ∇_W[2]J = (ŷ − y) · a^[1]ᵀ

That ŷ−y term is exactly the "predicted minus actual" error from §4 — the output layer of a network is a logistic-regression unit, just one whose input a^[1] happens to be the previous layer's output rather than raw features. The hidden layer's gradient follows the same chain-rule logic, carried one link further back: informally, its local error signal is the output layer's error, weighted back through W^[2] and scaled by how sensitive its own activation was to its input. That's the whole mechanism, repeated once per layer, output backward to input — and why very deep networks can hit the vanishing/exploding gradient issues in §6: each extra layer means one more multiplication in this backward chain.

Worked example

Using the forward pass above (ŷ≈0.555, a^[1]≈0.599), true label y=1, learning rate η=0.1. Invented toy step, not a real training run.

∇_z[2]J = ŷ−y = 0.555−1 = −0.445. ∇_W[2]J = (ŷ−y)·a^[1]ᵀ = −0.445×0.599 ≈ −0.267. Since z^[2] depends on b^[2] with coefficient 1: ∇_b[2]J = −0.445.

W^[2]_new = 0.7 − 0.1×(−0.267) ≈ 0.727. b^[2]_new = −0.2 − 0.1×(−0.445) ≈ −0.156. Both parameters moved in the direction that would push ŷ higher, toward the true label of 1 — exactly right, since the network under-predicted. The same style of computation, one layer further back, updates W^[1] and b^[1], using the propagated error instead of ŷ−y directly.

Notation: ℓ = number of layers · n^[i] = units in layer i (n^[0]=inputs, n^[ℓ]=outputs) · a^[i] = activations of layer i (a^[ℓ]=ŷ) · g^[i] = layer i's activation function · W^[i], b^[i] = layer i's parameters · z^[i] = W^[i]a^[i−1]+b^[i].

Training loop: ① forward propagation — push input through every layer to compute ŷ, then compute cost J; ② backpropagation — starting from the output layer, apply the chain rule to get every parameter's gradient, and update via gradient descent. Repeat until convergence or a max iteration count.

6

Hyperparameters, Activations & Why Deep Training Is Hard

Everything so far assumed a network's shape and activation functions were already decided. In practice, those choices — collectively hyperparameters, to distinguish them from the weights/biases the network learns on its own — are set by you before training starts, and matter enormously.

Network size — depth × width — is the most consequential hyperparameter, fixed going into training; gradient descent never changes it. A bigger network has more capacity to fit complex patterns, but also more capacity to fit noise (overfitting), and costs more to train and run. A smaller network trains faster and generalizes more predictably, but risks underfitting. Practical advice: start small, grow based on validation performance (not training performance — that's how overfitting sneaks in undetected), and add mitigations like dropout (randomly disabling a fraction of neurons each training step, forcing the network not to over-rely on any one) and early stopping (halting once validation performance stops improving, even if training performance is still climbing).

Activation functions

Why does the activation function g(·) matter at all — why not just skip it and stack raw weighted sums? A linear function of a linear function is still linear. If every layer were just z=Wa+b with no non-linear step, an entire ten-layer network would collapse mathematically into a single linear-regression model, no matter how many layers. The activation function is what lets depth actually buy you something.

A good activation function also needs to be: differentiable (backprop's chain rule requires taking its derivative at every layer), reasonably bounded in output (unbounded activations make training numerically unstable), and cheap to compute.

FunctionFormula
Sigmoidσ(x) = 1/(1+e⁻ˣ), range (0,1)
tanhrange (−1,1)
ReLUmax(0, x)
Leaky ReLUmax(0.1x, x)
ELUx if x≥0; α(eˣ−1) if x<0

Sigmoid is what you've used throughout §4–5 for its clean probability interpretation, but for hidden layers ReLU (and variants) is the more common modern default — essentially free to compute and, as below, avoids a specific failure mode sigmoid is prone to in deep stacks.

Python note

When you write Dense(64, activation='relu') or Dense(1, activation='sigmoid'), that activation= argument names one of the functions above — Keras wires in the function (and its derivative, for backprop) automatically. You'll see 'relu', 'sigmoid', and 'softmax' used this way throughout the Sprint Exercises' Keras model.

What makes deep nets hard to train

  • Optimization difficulty — two problems hide here. Vanishing gradients: backpropagation computes each layer's gradient by multiplying the next layer's gradient by additional chain-rule factors. If those factors are consistently less than 1 (easy with sigmoid/tanh, whose derivatives are always ≤0.25), the product shrinks toward zero across many layers — the earliest layers receive a signal so tiny they barely update. Saddle points: in high-dimensional cost surfaces, gradient descent can get stuck somewhere flat in every direction locally checked but not actually the minimum.
  • Overfitting — a large enough network can simply memorize the training set's noise rather than the underlying trend: great training performance, poor validation/test performance.
  • Training instability — the mirror of vanishing gradients: if the chain-rule factors are consistently greater than 1, the product grows without bound backward (exploding gradients), producing update steps so large they destabilize the weights, especially in very deep stacks.
CategoryTechniques
OptimizationRight optimizer (SGD, Adam), learning-rate decay, good weight init, gradient clipping
RegularizationDropout, L1/L2, early stopping, batch/layer normalization
ArchitectureMatch the architecture to the task (CNNs for images, RNNs for sequences)
Python note

SGD (§7) and Adam (an adaptive optimizer that automatically tunes the effective step size per parameter as training progresses) are the two optimizers you'll see named constantly in Keras, either as strings (optimizer='adam') or configurable objects (keras.optimizers.SGD(learning_rate=0.01)) when you need direct control.

7

Gradient Descent at Scale

Full-batch gradient descent doesn't survive contact with real dataset sizes.

Every gradient formula so far — §2's linear regression, §4's logistic regression, §5's backprop — was written as a sum over all M training examples. Fine on paper and on a handful of toy points; not fine the moment your dataset is the size of anything real.

The motivating number: 30,000 features, 1,000,000 data points, 1,000 training epochs, using the full-batch gradient which touches every feature of every point every epoch. Multiply it out: 30,000 × 1,000,000 × 1,000 = 3×10¹³ — thirty trillion individual term evaluations before training even finishes. Not merely slow — on realistic hardware and time budgets, simply infeasible.

Batch GDStochastic GDMini-Batch GD
Each step usesThe full datasetOne random pointA small batch
Cost curveSmoothHighly fluctuatingMildly fluctuating
ProsExact gradient, ideal for convex problemsFast updates, can escape local minima, memory-efficientStable and fast — best of both
ConsSlow, expensive per stepNoisy, sensitive to outliers—

Why does SGD's cost curve fluctuate? Each step's "gradient" is now only an estimate, computed from a single randomly chosen point rather than the true average over all M points, so it can point in a noticeably wrong direction on any given step — noisy, but each step is nearly free, and you get to take vastly more of them per second. Mini-batch GD is the practical compromise almost everyone uses: average the gradient over a modest batch (commonly 32–256 points) — enough to smooth out most of the noise, few enough to keep each step cheap.

Learning-rate schedules

A single fixed α forces a trade-off across the whole run: large enough for meaningful early progress, small enough not to overshoot near the minimum. A learning-rate schedule resolves this by shrinking α over the course of training:

Step decay: α = α₀ × factor^(epoch / decay_step) Exponential decay: α = α₀ × e^(−decay_rate × epoch) 1/t decay: α = α₀ / (1 + decay_rate × epoch)

Step decay drops by a fixed multiplicative factor every decay_step epochs (a staircase); exponential decay shrinks continuously every epoch; 1/t decay also shrinks continuously but more slowly (hyperbolically) over time. None is "the correct one" in any absolute sense — they're different shrinkage shapes to pick between based on how the cost curve behaves.

Course guidance: start with Adam for most tasks, since its per-parameter adaptive step sizes tend to work well without much tuning; reach for plain SGD paired with an explicit decay schedule when training very large models where stability matters more than convenience; and regardless of optimizer, watch the actual cost curve rather than assuming one is automatically right for your problem.

Input normalization

A different scale problem: if features live on wildly different numeric scales, the cost surface gets stretched into a long, narrow, skewed shape — a valley steep on one side, nearly flat on the other. Gradient descent handles that badly, since one learning rate has to serve both a steep and a shallow direction at once, forcing tiny, cautious steps everywhere. The fix: rescale every feature onto a comparable scale before training — z-score standardization.

μ = (1/M) Σ x⁽ⁱ⁾ σ² = (1/M) Σ (x⁽ⁱ⁾ − μ)² x_normalized = (x − μ) / σ
Rule

μ and σ are computed on training data only and become part of the saved model — reuse the exact same values on test/production data (see Module 2 §2 for the same rule applied to scikit-learn scalers). Recomputing μ and σ separately on the test set would let the test set's own statistics leak into how it's preprocessed — a subtle form of the same "the model has seen information it shouldn't have" problem that shows up elsewhere in this bootcamp.

Closing recipe

Pulling every piece of this module together, training essentially any model — from §4's single-neuron logistic regression through §5–6's deep networks — comes down to the same six-step recipe:

  1. Choose a framework
  2. Build the model (size, normalization, dropout, …)
  3. Define the cost function
  4. Select an optimizer and learning rate
  5. Apply backpropagation
  6. Tune hyperparameters

"Neural networks are the second-best way to do everything" — a specialized method often beats a generic NN for any one task, but a NN is a strong fallback when nothing more specialized fits. If you know your problem is, say, a time series or an image, a purpose-built architecture will usually outperform a generic dense network — but when you don't have that domain-specific tool, or aren't sure yet what shape the problem has, the machinery in this module is the reliable, general-purpose fallback.

Exercise 9 — Logistic Regression vs. a Neural Network on CIFAR-10

Same 10-class image classification task (32×32×3 pixels, flattened), two models: LogisticRegression(solver='saga') and a small Keras net (Flatten → Dense(128, relu) → Dense(10, softmax)).

Result

Logistic regression: 34% test accuracy. The neural network: 45% after 50 epochs — both well above the 10% random baseline, but the gap between them is the whole point of this module's title.

Gotcha

Sweeping the learning rate (0.001 / 0.01 / 0.1, §7) requires rebuilding and recompiling the model each time — reusing one already-trained model across learning rates silently invalidates the comparison. The observed pattern matches the theory exactly: 0.001 is stable but slow, 0.01 balances convergence and generalization best, 0.1 overshoots and destabilizes training.

In §1's framing, what is a perceptron structurally identical to, and at how many hidden layers does "deep learning" conventionally start?

A perceptron performs exactly the same computation as logistic regression (weighted sum, then a squashing function), and a network is many such units stacked in layers. Deep learning conventionally starts at three or more hidden layers.

In §2's worked MSE example, for the toy dataset (1,3),(2,5),(3,7) with candidate weights ω=1.5, b=1, what are the three predicted ŷ values and the resulting cost J(θ)?

Predictions are ŷ=2.5, 4.0, 5.5 for x=1,2,3, giving residuals 0.5, 1.0, 1.5 and squared residuals summing to 3.5. With M=3 (2M=6), J(θ) = 3.5/6 ≈ 0.583.

Continuing that same toy dataset (ω=1.5, b=1, α=0.1) in §3's gradient-descent worked example, what are the computed bias and weight gradients, and the updated ω and b after one step?

∂J/∂b = −1.0 and ∂J/∂ω ≈ −2.333. The updated values are b_new = 1.1 and ω_new ≈ 1.733.

For the §4 toy patient example (w=[0.5, −0.3], b=0.1, x=[2,1], true label y=1), what are z, ŷ, and the binary cross-entropy cost J?

z = 0.5×2 + (−0.3)×1 + 0.1 = 0.8, giving ŷ = σ(0.8) ≈ 0.690. Since y=1, J = −log(0.690) ≈ 0.371.

In §5's worked forward-propagation example (2 inputs, 1 hidden neuron, 1 output neuron, both sigmoid; x=[1.0,0.5], W[1]=[0.4,−0.2], b[1]=0.1, W[2]=0.7, b[2]=−0.2), what are z[1], a[1], z[2], and the final ŷ?

z[1] = 0.4, a[1] = σ(0.4) ≈ 0.599; z[2] = 0.7×0.599 − 0.2 ≈ 0.219, and ŷ = a[2] = σ(0.219) ≈ 0.555.

Continuing that forward pass in §5's backpropagation worked example (true label y=1, η=0.1), what are ∇z[2]J and ∇W[2]J, and what are the updated W[2] and b[2]?

∇z[2]J = ŷ−y = 0.555−1 = −0.445, and ∇W[2]J = −0.445×0.599 ≈ −0.267 (with ∇b[2]J = −0.445). The updated values are W[2] ≈ 0.727 and b[2] ≈ −0.156.

Per §6, why are sigmoid and tanh activations especially prone to causing vanishing gradients in deep networks?

Backpropagation multiplies each layer's gradient by additional chain-rule factors, and sigmoid/tanh derivatives are always ≤0.25, so those factors are consistently less than 1. Multiplying many such factors together shrinks the product toward zero across layers, leaving the earliest layers with almost no update signal.

What is the motivating calculation in §7 for why full-batch gradient descent doesn't scale, and what total does it produce?

With 30,000 features, 1,000,000 data points, and 1,000 training epochs, full-batch gradient descent requires 30,000 × 1,000,000 × 1,000 = 3×10¹³ (thirty trillion) individual term evaluations. The module calls this simply infeasible on realistic hardware and time budgets.

According to the "Rule" callout in §7, on what data must the normalization statistics μ and σ be computed, and what goes wrong if you don't follow that rule?

μ and σ must be computed on training data only and then reused (as part of the saved model) on test/production data. Recomputing them separately on the test set would let the test set's own statistics leak into its preprocessing — a form of data leakage.
