LLM & RAG Pipeline

Condensed reference
Language models → decoding → retrieval-augmented generation

From "a neuron is logistic regression" to full retrieval-augmented generation: how LLMs are trained, how they generate text token by token, and why RAG exists at all.

1

Language Models: Foundations

Softmax (Ch.5) is the bridge: it's exactly what an LLM uses to pick its next word.

A language model predicts the next token given everything before it: P(xₜ | x₁, …, xₜ₋₁). Training is self-supervised — no manual labels needed, since the next word in raw text is the label. This scales to massive corpora and teaches syntax and semantics implicitly.

Context entirely determines the prediction. Same fill-in-the-blank prompt — "Honey, can you pass me the ___" — gets a wildly different probability distribution depending on the scene:

ContextP(Salt)P(Pepper)P(Gun)
Family dinner scene0.540.330.13
Tense confrontation scene0.160.180.66

Because next-token prediction is so general, almost any NLP task can be reframed as "find the right prompt":

TaskGoal
Sentiment analysisDetermine emotional tone/opinion
SummarizationCondense long text, keep key info
Question answeringAnswer based on context/knowledge base
Named entity recognitionIdentify/classify proper nouns (person, org, …)
Text classificationAssign categories/labels (spam, topic)
Machine translationTranslate between languages
Text generationProduce new coherent text from a prompt

Text is harder to represent than audio or DNA because it's unstructured (no fixed numeric format), ambiguous ("bank" = financial institution or riverbank), and context-dependent ("cold" = temperature or illness).

2

Training & Inference

Predict-the-next-token, billions of times over — then decode one token at a time at inference.

Training pipeline

  1. Collect a large text corpus — Common Crawl, Wikipedia, Books, WebText.
  2. Tokenize — split text into words, subwords, or characters, each mapped to an integer ID in a vocabulary table. A larger vocabulary means more unique tokens available.
  3. Causal masking — at each position the model may only see prior tokens, forcing it to learn to predict what comes next; an attention mechanism relates tokens to each other.
  4. Repeat across the whole corpus, billions of times (self-supervised learning). This is extremely compute-intensive — why foundation models are pretrained by a handful of large labs, then fine-tuned by everyone else.
Gotcha

The LLM's output layer is a softmax over the vocabulary — its size equals the vocabulary size, not the embedding dimension or context length.

Inference: autoregression & decoding

Flow: text → tokenizer → embedding lookup → decoder-only transformer → linear layer → softmax → a probability per vocabulary token.

  • Greedy decoding — always pick the highest-probability token. Deterministic: identical input always produces identical output.
  • Autoregression — each generated token is appended back to the context to predict the next one ("Once upon" → +"a" → "Once upon a" → +"time" → …).

Pure greedy decoding is safe but repetitive and unimaginative. Temperature fixes this by reshaping the distribution before sampling:

p(zᵢ) = e^(zᵢ/T) / Σⱼ e^(zⱼ/T)

T = 1.0 is the unscaled default; T < 1.0 sharpens the distribution (more deterministic, less creative); T > 1.0 flattens it (more random, more creative). Top-k/top-p sampling can be layered on top of temperature.

Note

ChatGPT is not a raw LLM — it's an LLM wrapped with prompt engineering, RLHF fine-tuning/alignment, conversation-memory handling, tool integration (search, code, images), and safety/moderation layers.

Why RAG?

A plain LLM chatbot has structural blind spots RAG is built to patch.

Pitfall of a plain LLMWhy it happens
Static knowledgeTrained on fixed data; blind to anything after the training cutoff
HallucinationConfidently fabricates answers, especially on niche topics
Context window limitsHard cap on how much text can be passed in at once
Domain knowledge gapsGeneric pretraining lacks company-specific/technical depth
No source attributionDoesn't show where an answer came from
Low explainabilityHard to verify how an answer was produced

4

The RAG Pipeline

An offline indexing phase, and an online query phase.

Indexing (offline): documents → chunk & preprocess → generate embeddings → store in a vector database.
Query (online): user question → embed the question → semantic search against the vector DB → ranked chunks → pass query + chunks to the LLM → generated answer.

Chunking

Split large documents into retrievable pieces without cutting mid-sentence or across semantic units. Each chunk carries metadata (title, source, page, section, tags) so retrieved results stay traceable.

text_splitter = RecursiveCharacterTextSplitter( chunk_size=50, chunk_overlap=20, # overlap avoids losing context at chunk boundaries )

Embeddings

A learned embedding space places semantically similar chunks close together — unlike one-hot encodings, which carry no notion of similarity at all. RAG typically uses sentence embeddings, extending word embeddings to whole passages.

Gotcha

Cosine distance (1 − cos θ) is a dissimilarity score — don't confuse it with cosine similarity itself.

Generation

The final prompt combines the query, the retrieved chunks, and a domain-specific instruction:

[User Question] How does the Marketing team make strategic decisions? [Context] - The Marketing team recently shifted focus to data-driven decision-making. - They rely on weekly reports and campaign retrospectives. - A/B testing, customer segmentation, and performance metrics. [Instruction] Using the provided context, answer the question concisely and cite your sources.
